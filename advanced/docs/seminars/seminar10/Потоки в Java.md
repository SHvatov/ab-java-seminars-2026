# Потоки в Java

---

## Поток Java и поток ОС

Классический (platform) поток Java — обёртка над потоком операционной системы в соотношении 1:1. За то, какой поток
окажется на ядре CPU, отвечает **планировщик ОС**: его алгоритм (вытесняющий, по приоритетам) и решения зависят от
системы, а не от JVM. Приоритет потока Java (`int` 1–10) — лишь подсказка планировщику.

Практические следствия дороговизны потока ОС:

- **Память** — свой стек (обычно ~1 МБ) плюс структуры ядра.
- **Переключение контекста** — сохранение/восстановление регистров, давление на кеши; при тысячах потоков накладные
  начинают доминировать.
- **Вывод** — потоков не может быть много (тысячи, не миллионы), их переиспользуют (пулы) вместо создания на задачу; это
  же мотивирует виртуальные потоки (много «потоков» на немногих потоках ОС).

## Состояния потока

`NEW` → `RUNNABLE` (готов/исполняется) → `TERMINATED`; из `RUNNABLE` поток может уйти в `BLOCKED` (ждёт монитор),
`WAITING`/`TIMED_WAITING` (ждёт условие/таймаут). `BLOCKED`/`WAITING` — простой с занятыми ресурсами; это проекция
состояний потока ОС.

## Создание, запуск, join

```java
void example(Runnable task, List<String> tickers, Quote[] results) throws InterruptedException {
    Thread thread = Thread.ofPlatform().name("worker").start(task);

    Thread[] threads = new Thread[tickers.size()];
    for (int i = 0; i < tickers.size(); i++) {
        int index = i;
        threads[i] = Thread.ofPlatform().start(() ->
                results[index] = load(tickers.get(index)));   // каждый — в свою ячейку
    }
    for (Thread t : threads) {
        t.join();   // ждём завершения
    }
}
```

Параллелизм без общего изменяемого состояния (каждый поток пишет в свою ячейку) безопасен без синхронизации. Проблемы
начинаются с общего состояния — следующий семинар.

## Прерывание

Кооперативный механизм: `interrupt()` выставляет флаг; блокирующие методы бросают `InterruptedException` и **сбрасывают**
флаг; его восстанавливают через `Thread.currentThread().interrupt()`. Проглоченное прерывание делает поток
неостановимым.

## Мостик к модели памяти

Даже без «явного» общего состояния параллельный код упирается в вопрос: гарантированно ли один поток видит записи
другого и в каком порядке? Обычный общий `int`-счётчик, увеличиваемый несколькими потоками, теряет обновления и может
быть невидим другим потокам. Почему так и как это чинить (`volatile`, `final`, атомарные операции, happens-before) —
в материале [«Java Memory Model»](./Java%20Memory%20Model.md).

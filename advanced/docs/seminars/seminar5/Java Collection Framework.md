# Java Collection Framework

---

## Что это

Java Collection Framework (JCF) — набор интерфейсов и реализаций структур данных в `java.util`. Framework отделяет
контракт структуры (`List`, `Set`, `Queue`, `Map`) от реализации (`ArrayList`, `HashSet`, `ArrayDeque`, `HashMap`),
позволяя программировать против интерфейса и выбирать реализацию по характеристикам её операций.

---

## Иерархия интерфейсов

```
Iterable
 └── Collection
      ├── List   — упорядоченная последовательность, дубликаты допускаются (ArrayList, LinkedList)
      ├── Set    — множество уникальных элементов (HashSet, LinkedHashSet, TreeSet)
      └── Queue  — очередь с дисциплиной обработки (ArrayDeque, LinkedList)

Map          — отображение «ключ → значение» (HashMap, LinkedHashMap, TreeMap)
```

`Map` не наследует `Collection` — отдельная иерархия: оперирует парами, а не элементами, метода `iterator()` не имеет,
перебирается через `keySet()`, `values()`, `entrySet()`.

---

## Сложность операций

| Операция | ArrayList | LinkedList | HashSet / HashMap | TreeSet / TreeMap |
|----------|-----------|------------|-------------------|-------------------|
| Поиск по ключу/значению | `O(n)` | `O(n)` | `O(1)`* | `O(log n)` |
| Добавление | `O(1)`** | `O(1)` | `O(1)`* | `O(log n)` |
| Доступ по индексу | `O(1)` | `O(n)` | — | — |
| Вставка/удаление в начало | `O(n)` | `O(1)` | — | — |

*в среднем, при равномерном распределении хешей. **амортизированно, с учётом расширения массива.

Асимптотика — главный, но не единственный критерий. `ArrayList` хранит данные подряд в одном массиве и дружелюбен к
кешу процессора; `LinkedList` — по узлу на элемент с двумя ссылками, что проигрывает по локальности даже там, где
асимптотика формально в его пользу. Разницу видно и на замере JMH, и на раскладке объектов через JOL.

---

## List

- `ArrayList` — поверх массива: индексный доступ `O(1)`, поиск `O(n)`, добавление в конец амортизированно `O(1)`,
  вставка в середину/начало `O(n)` (сдвиг элементов). Реализация по умолчанию.
- `LinkedList` — двусвязный список: вставка/удаление с концов `O(1)`, индексный доступ `O(n)`. Оправдан редко.

Быстрый индексный доступ формализован маркерным интерфейсом `RandomAccess`: его реализует `ArrayList`, но не
`LinkedList`. Обобщённые алгоритмы (`Collections.binarySearch`, `shuffle`) проверяют `instanceof RandomAccess` и
выбирают индексный либо итераторный обход — поэтому обход `LinkedList` по индексу `get(i)` вырождается в `O(n²)`.

---

## Set

- `HashSet` — `O(1)` операции, порядок не определён; поверх `HashMap`, уникальность через `equals`/`hashCode`.
- `LinkedHashSet` — `O(1)`, порядок добавления сохраняется.
- `TreeSet` — `O(log n)`, элементы отсортированы (`Comparable`/`Comparator`).

`Set.add` возвращает `false`, если элемент уже присутствует — предварительный `contains` не нужен.

---

## Queue

Базовые методы — `offer` (в хвост) / `poll` (из головы, `null` на пустой) и бросающие исключение `add`/`remove`.
`ArrayDeque` — реализация общего назначения на кольцевом буфере: операции с обоими концами `O(1)`, работает как
FIFO-очередь и как LIFO-стек, предпочтительнее `LinkedList` и устаревшего `Stack`.

---

## Map

- `HashMap` — `O(1)` в среднем, порядок не определён.
- `LinkedHashMap` — `O(1)`, порядок добавления ключей.
- `TreeMap` — `O(log n)`, ключи отсортированы, доступны запросы по диапазону.

Равенство ключей строгое, по `equals`/`hashCode`. Строковый ключ чувствителен к регистру — при необходимости
нормализуется (например, к верхнему регистру) в одном месте, и при записи, и при чтении.

## Iterable, iterator() и fail-fast

Всё, что реализует `Collection`, реализует `Iterable`: перебирается for-each, отдаёт `Iterator`. Цикл for-each —
синтаксический сахар над `Iterator`.

Коллекции JCF — **fail-fast**: каждая структурная модификация увеличивает `modCount`; итератор запоминает его при
создании и сверяет на каждом `next()`. Изменение коллекции в обход итератора (прямой `remove` внутри for-each) даёт
расхождение и `ConcurrentModificationException` — не про многопоточность, одного потока достаточно.

```java
void example(List<String> tickers) {
    Iterator<String> it = tickers.iterator();
    while (it.hasNext()) {
        if (it.next().startsWith("T")) {
            it.remove(); // безопасно: синхронно обновляет modCount
        }
    }
}
```

Для случая «удалить всё по условию» — `removeIf(predicate)` (Java 8+), внутри тот же итератор.

## За пределами java.util

Экосистема предлагает коллекции под специализированные задачи:

- **Guava** — иммутабельные коллекции (`ImmutableMap`/`ImmutableList` — настоящая неизменяемая копия, а не обёртка) и
  мультиотображения (`Multimap` вместо ручного `Map<K, List<V>>`).
- **Vavr** — персистентные коллекции: «модификация» (`append`/`put`) возвращает новую версию, старая неизменна, обе
  дёшево делят внутренние узлы (structural sharing).
- **Apache Commons Collections** — теоретико-множественные операции (`CollectionUtils.intersection`), мультимножества
  (`Bag`), дополнительные структуры.
- **fastutil** (и подобные — Trove, Eclipse Collections) — примитивные коллекции: хранят `int[]`/`double[]` напрямую,
  экономят память на отказе от boxing, смыкаются с разговором о раскладке объектов.

Тянуть внешнюю библиотеку стоит осознанно, под конкретную нужду, а не по умолчанию.

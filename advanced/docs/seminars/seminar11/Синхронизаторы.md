# Синхронизаторы

---

## Что это

Синхронизаторы (`java.util.concurrent`) — утилиты координации потоков поверх мониторов и CAS. Они дают более высокий
уровень абстракции, чем `synchronized`/`wait`/`notify`: вместо ручного управления монитором — готовая семантика «ждать
N», «ограничить одновременность», «собрать в точке». Все построены на общей основе — `AbstractQueuedSynchronizer` (AQS),
управляющей очередью ожидающих потоков и атомарным состоянием.

---

## CountDownLatch

Одноразовый барьер «дождаться N событий». Инициализируется числом; `countDown()` уменьшает счётчик; `await()` блокирует,
пока счётчик не дойдёт до нуля, после чего пропускает всех и остаётся открытым навсегда.

```java
void example(int workers) throws InterruptedException {
    CountDownLatch ready = new CountDownLatch(workers);
    // в каждом воркере по завершении подготовки: ready.countDown();
    ready.await();          // главный поток ждёт, пока все N не подготовятся
}
```

Применение: дождаться инициализации из нескольких источников; одновременный старт (общий «стартовый» латч).

## CyclicBarrier

Многоразовая точка сбора: N потоков вызывают `await()` и продолжают вместе, когда все собрались. В отличие от
`CountDownLatch`, барьер переиспользуется (после срабатывания сбрасывается) и может выполнить действие при срабатывании.

```java
void example(int parties) {
    CyclicBarrier barrier = new CyclicBarrier(parties, () -> System.out.println("фаза завершена"));
    // в каждом потоке в конце фазы: barrier.await();
}
```

Применение: итеративные параллельные алгоритмы, где на каждой фазе потоки должны синхронизироваться.

## Semaphore

Ограничение числа одновременных участников. Держит набор разрешений; `acquire()` занимает (ждёт, если свободных нет),
`release()` возвращает.

```java
void example(QuoteSource source, String ticker) throws InterruptedException {
    Semaphore limit = new Semaphore(3);   // не более 3 одновременных обращений к API
    limit.acquire();
    try {
        source.fetch(ticker);
    } finally {
        limit.release();
    }
}
```

Применение: рейт-лимитер к внешнему API (ограничение по коду `429 Too Many Requests`), пул ограниченных ресурсов.

## Phaser

Гибкий многофазный барьер: как `CyclicBarrier`, но число участников можно менять динамически (`register`/`arriveAndDeregister`),
а фазы нумеруются. Подходит для задач, где число потоков меняется между фазами.

```java
void example() {
    Phaser phaser = new Phaser(1);          // регистрируем себя
    phaser.register();                      // добавили участника
    phaser.arriveAndAwaitAdvance();         // отметиться и ждать перехода к следующей фазе
    phaser.arriveAndDeregister();           // выйти
}
```

## StampedLock

Read/write-блокировка с тремя режимами: запись (эксклюзивно), чтение (разделяемо) и **оптимистичное чтение** — без
блокировки вовсе: читаем, затем проверяем `validate(stamp)`, не изменилось ли за это время; если изменилось — перечитываем
под настоящей read-блокировкой.

```java
void example(StampedLock lock, int[] value) {
    long stamp = lock.tryOptimisticRead();
    int v = value[0];
    if (!lock.validate(stamp)) {            // кто-то писал — читаем надёжно
        stamp = lock.readLock();
        try { v = value[0]; } finally { lock.unlockRead(stamp); }
    }
}
```

На преобладающих чтениях быстрее `ReentrantReadWriteLock`. Не реентрантен — требует аккуратности.

## Exchanger

Точка обмена объектами между **двумя** потоками: каждый приносит объект, оба получают объект партнёра. Обмен происходит,
только когда оба готовы.

```java
void example(Exchanger<byte[]> exchanger, byte[] mine) throws InterruptedException {
    byte[] theirs = exchanger.exchange(mine);   // блокирует до встречи с партнёром
}
```

Применение: конвейеры «наполнить/обработать» с обменом буферами.

---

## Правило выбора

| Задача | Инструмент |
|---|---|
| Дождаться N событий (однократно) | `CountDownLatch` |
| Собрать N потоков в точке (многократно) | `CyclicBarrier` |
| Динамическое число участников, фазы | `Phaser` |
| Ограничить одновременность | `Semaphore` |
| Много чтений, редко запись | `StampedLock` (оптимистичное чтение) |
| Обмен между двумя потоками | `Exchanger` |

И общее правило: блокирующие операции — с таймаутом (`tryAcquire`/`tryLock` с временем), иначе одна зависшая задача
может заблокировать систему.

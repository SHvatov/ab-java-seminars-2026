# Эффективная работа с диском

Диск на порядки медленнее памяти, а каждое обращение к нему через API — системный вызов. Организация чтения и записи
влияет на производительность не меньше объёма данных. Материал разбирает буферизацию, минимизацию системных вызовов,
memory-mapped файлы и zero-copy.

## 1. Стоимость обращения к диску

Задержка диска (даже SSD) на несколько порядков выше доступа к памяти. Сверх задержки каждая операция чтения/записи —
системный вызов: переключение в режим ядра и обратно, копирование данных между буфером ядра и буфером приложения. Общий
принцип: обращения к диску должны быть **редкими и крупными**, а не частыми и мелкими.

---

## 2. Буферизация

Буфер накапливает данные, чтобы обмениваться с диском крупными блоками. Без буфера чтение по байту породило бы системный
вызов на каждый байт; буфер собирает блок (обычно несколько КБ) за один вызов.

```java
void example(Path file) throws IOException {
    try (BufferedReader reader = Files.newBufferedReader(file)) {
        String line;
        while ((line = reader.readLine()) != null) {
            process(line);
        }
    }
}
```

`BufferedWriter` накапливает записи и сбрасывает блоком при заполнении, `flush()` или закрытии. На уровне каналов ту же
роль играет `ByteBuffer`.

---

## 3. Целиком против потоково

Маленький файл — целиком (`Files.readAllBytes`/`readString`), одна операция. Большой — потоково (`Files.lines`,
буферизованный канал), не загружая в память. Ошибка в обе стороны: большой лог в `String` — риск `OutOfMemoryError`;
маленький конфиг ручным потоковым циклом — лишняя сложность.

---

## 4. Минимизация системных вызовов

Каждый `write` — переход в ядро. Данные выгодно сформировать в памяти и записать одной операцией:

```java
void example(Path file, byte[] json) throws IOException {
    Files.write(file, json);   // один системный вызов на весь файл
}
```

---

## 5. Memory-mapped файлы

`FileChannel.map` отображает файл (или его участок) в виртуальную память процесса — `MappedByteBuffer`. После этого файл
читается и пишется как массив в памяти, а подкачку страниц с диска и обратно берёт на себя ОС (page cache). Для больших
файлов с произвольным доступом это устраняет явные системные вызовы `read`/`write` на каждое обращение.

```java
void example(Path file) throws IOException {
    try (FileChannel channel = FileChannel.open(file, StandardOpenOption.READ)) {
        MappedByteBuffer mapped = channel.map(FileChannel.MapMode.READ_ONLY, 0, channel.size());
        byte first = mapped.get(0);   // доступ как к памяти, без явного read
    }
}
```

Цена — отображение имеет накладные расходы на установку и не оправдано для маленьких файлов; управление сбросом
изменённых страниц (`force()`) и временем жизни отображения требует аккуратности.

---

## 6. Zero-copy передача

Копирование файла обычным способом гоняет данные диск → буфер ядра → буфер приложения → буфер ядра → диск. `FileChannel.transferTo`/`transferFrom`
позволяют ОС передать данные между каналами, минуя буфер приложения (потенциально zero-copy через `sendfile`):

```java
void example(FileChannel in, FileChannel out) throws IOException {
    in.transferTo(0, in.size(), out);   // передача на уровне ОС, без копий в коде
}
```

Выигрыш заметен на больших объёмах (раздача файлов, репликация); для мелких — незначителен.

---

## 7. Практика для приложения

Данные Market Pulse — десятки небольших JSON. Для них достаточно `Files.write`/`readString` целиком и `Files.list` для
обхода; буферизация, mmap и zero-copy — инструменты для больших объёмов. Их важно знать, чтобы при росте данных (история
котировок, логи) выбрать правильный механизм, а не упереться в производительность.

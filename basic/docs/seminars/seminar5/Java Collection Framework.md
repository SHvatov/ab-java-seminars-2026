# Java Collection Framework

---

## Что это

Java Collection Framework (JCF) — набор интерфейсов и готовых реализаций структур данных в стандартной библиотеке
(`java.util`). Вместо сырого массива с ручным управлением размером и индексами JCF предлагает типовые структуры под
разные задачи: последовательности, множества, очереди, отображения.

---

## Иерархия интерфейсов

```
Iterable
 └── Collection
      ├── List   — упорядоченная последовательность, допускает дубликаты (ArrayList, LinkedList)
      ├── Set    — множество уникальных элементов (HashSet, LinkedHashSet, TreeSet)
      └── Queue  — очередь, обработка по дисциплине FIFO/LIFO (ArrayDeque, LinkedList)

Map          — отображение «ключ → значение» (HashMap, LinkedHashMap, TreeMap)
```

`Map` **не** наследует `Collection` — это отдельная иерархия. У `Map` нет `iterator()`; она перебирается через
`keySet()`, `values()` или `entrySet()`. Причина: `Map` хранит пары «ключ-значение», а не отдельные элементы, и не
вписывается в контракт `Collection<E>`.

---

## List — упорядоченная последовательность

Хранит элементы в порядке добавления, допускает дубликаты, даёт доступ по индексу.

- `ArrayList` — поверх массива; индексный доступ `get(i)` за `O(1)`, поиск по значению `contains` за `O(n)`,
  добавление в конец амортизированно `O(1)`.
- `LinkedList` — двусвязный список; вставка/удаление в известной позиции `O(1)`, но индексный доступ `O(n)`.

По умолчанию — `ArrayList`; `LinkedList` оправдан редко.

---

## Set — множество уникальных элементов

Не допускает дубликатов; `add` возвращает `false`, если элемент уже присутствует. Проверка `contains` — основная
операция.

- `HashSet` — `O(1)` на `add`/`contains`/`remove`, порядок обхода не определён.
- `LinkedHashSet` — то же `O(1)`, но сохраняет порядок добавления.
- `TreeSet` — хранит элементы отсортированными, операции `O(log n)`.

Уникальность в `HashSet`/`LinkedHashSet` определяется парой `equals`/`hashCode` элемента.

---

## Queue — очередь

Обработка элементов по дисциплине порядка. Базовая пара методов — `offer` (добавить в хвост) и `poll` (извлечь из
головы, `null` на пустой очереди). Есть бросающие исключение аналоги `add`/`remove`.

- `ArrayDeque` — рекомендованная реализация общего назначения (быстрее `LinkedList`), работает и как FIFO-очередь, и
  как LIFO-стек.

---

## Map — отображение «ключ → значение»

Хранит пары; поиск, вставка и удаление — по ключу.

- `HashMap` — `O(1)` в среднем на `get`/`put`/`containsKey`, порядок не определён.
- `LinkedHashMap` — то же `O(1)`, сохраняет порядок добавления ключей.
- `TreeMap` — ключи отсортированы, операции `O(log n)`.

Равенство ключей определяется их `equals`/`hashCode`. Строковый ключ чувствителен к регистру: `"sber"` и `"SBER"` —
разные ключи, поэтому ключ имеет смысл нормализовать (например, к верхнему регистру) в одном месте — и при записи, и
при чтении.

---

## Сложность операций: чем руководствоваться при выборе

| Операция | ArrayList | LinkedList | HashSet / HashMap | TreeSet / TreeMap |
|----------|-----------|------------|-------------------|-------------------|
| Поиск по ключу/значению | `O(n)` | `O(n)` | `O(1)` | `O(log n)` |
| Добавление | `O(1)`* | `O(1)` | `O(1)` | `O(log n)` |
| Доступ по индексу | `O(1)` | `O(n)` | — | — |

*амортизированно, с учётом периодического расширения массива.

Главный критерий выбора — какая операция на структуре частая и во сколько она обходится при росте данных. Если
основная операция — поиск по ключу, hash-структура (`Map`/`Set`) не зависит от размера, тогда как линейный поиск в
`List` замедляется пропорционально количеству элементов.

## Iterable и iterator()

Всё, что реализует `Collection`, реализует и `Iterable` — значит, перебирается циклом for-each и отдаёт `Iterator`.
Цикл for-each — синтаксический сахар над `Iterator`:

```java
void example(List<String> tickers) {
    for (String ticker : tickers) {   // под капотом — tickers.iterator()
        System.out.println(ticker);
    }
}
```

У каждой коллекции есть и метод `stream()` — вход в Stream API, декларативную обработку данных. Это отдельный слой
абстракции поверх той же коллекции.

---

## Изменение коллекции во время обхода: fail-fast

Прямое удаление элемента из коллекции во время for-each по ней роняет программу:

```java
void example(List<String> tickers) {
    for (String ticker : tickers) {
        if (ticker.startsWith("T")) {
            tickers.remove(ticker); // ConcurrentModificationException
        }
    }
}
```

Коллекции JCF работают по принципу **fail-fast**: если коллекция структурно изменилась в обход итератора, итератор
замечает это и бросает `ConcurrentModificationException`, а не продолжает молча с испорченным состоянием. Речь не
обязательно о многопоточности — одного потока, меняющего коллекцию мимо итератора, достаточно.

---

## Iterator.remove() — безопасное удаление по ходу обхода

Чтобы удалять во время перебора, нужно работать с итератором явно и удалять через него:

```java
void example(List<String> tickers) {
    Iterator<String> it = tickers.iterator();
    while (it.hasNext()) {
        String ticker = it.next();
        if (ticker.startsWith("T")) {
            it.remove(); // удаляет последний возвращённый next() элемент
        }
    }
}
```

`Iterator.remove()` удаляет последний элемент, возвращённый `next()`; вызов до `next()` или дважды подряд —
`IllegalStateException`. Начиная с Java 8 у коллекций есть `removeIf(predicate)` — компактная альтернатива для случая
«удалить всё, подходящее под условие», внутри использующая тот же механизм.

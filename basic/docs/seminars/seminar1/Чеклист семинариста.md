### Этап 4. Доменная модель Market Pulse

- [ ] **Шаг 4.1.** Разобрать вместе со студентами уже данные `Currency` и `Instrument`: почему поля `private final`,
  почему валидация тикера — в конструкторе. Показать защиту инварианта.
- [ ] **Шаг 4.2.** Показать уже существующий `@Deprecated`-класс `InstrumentFormatter` (наивный `instanceof`-вариант).
  Обсудить со студентами, почему это плохо. Вместе отрефакторить в полиморфизм: реализовать `getDescription()` в
  `Stock`/`Bond`/`Etf`, удалить `InstrumentFormatter`.
- [ ] **Шаг 4.3.** Показать на расчёте (цена × доходность), почему `double` не годится для денег; ввести
  `BigDecimal` с явным `RoundingMode`.
- [ ] **Шаг 4.4.** Обратить внимание, что `getDividends` бросает исключение в `Stock`. Разобрать дилемму, которая
  возникла бы, попробуй мы добавить этот метод в `Instrument` (что возвращать в `Bond`/`Etf`?). Прийти к нарушению
  LSP — метод должен остаться только в `Stock`, реализовать его там.
- [ ] **Шаг 4.5.** Показать уже существующий `@Deprecated`-класс `StockSnapshot` (наивная попытка через
  наследование), объяснить, где она ломается. Написать `Quote` с нуля как агрегацию, удалить `StockSnapshot`.
  Объяснить студентам, почему `instanceof` в `Quote.getDividends()` — не то же самое, что наивное решение из шага
  4.2 (см. заметку в плане).
- [ ] Перед шагом 4.6 запушить текущее состояние кода (`Currency`…`Quote`) в репозиторий, чтобы студенты подтянули
  актуальное состояние себе.
- [ ] **Шаг 4.6 — самостоятельно.** Раздать студентам функциональные требования и интерфейс `Portfolio`/`Position`
  (массив, не коллекция — JCF ещё не пройден). Решение не подсказывать. После — сверить с подготовленным эталоном,
  обсудить композицию в контрасте с агрегацией из `Quote`.

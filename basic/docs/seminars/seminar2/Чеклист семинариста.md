# Семинар 2. Чеклист семинариста

**До семинара:**

- [ ] Убедиться, что презентация (SOLID → паттерны GoF → picocli и `pom.xml`) есть в репозитории и отображается
  корректно.
- [ ] Проверить исходный код семинара: проект собирается; `StockFactory`/`BondFactory`/`EtfFactory.create()` бросают
  исключение — ожидаемо, реализуются на занятии (этап 4); `TypeFilter`/`NoOpFilter.matches()` тоже бросают
  исключение — их реализуют студенты самостоятельно (этап 6). Остальной код (доменная модель, `Iterator`,
  CLI-команды) уже рабочий.
- [ ] Подготовить у себя готовую реализацию `StockFactory`/`BondFactory`/`EtfFactory` и `TypeFilter`/`NoOpFilter` —
  эталон для сверки по ходу семинара; студентам заранее не показывать.
- [ ] Подготовить доску (WhiteBoard / доска в Толке) для фиксации таблицы «задача → паттерн-кандидат» (этап 3).

**По ходу семинара:**

### Этап 1. Теория: принципы SOLID

- [ ] Провести теорию по материалу «Принципы SOLID»: LSP → ISP → SRP → OCP → DIP (обзорно) → KISS и DRY.
- [ ] Показать, что `getDividends` уже объявлен только в `Stock` (семинар 1) — LSP не нарушен; интерфейс
  `DividendPaying` лишь называет эту способность явно (ISP).
- [ ] Явно оговорить: полноценный DIP через dependency injection — тема следующего учебного года (Spring), не этого
  курса; пример на своём коде — конструкторная передача `repository` в CLI-команды.

### Этап 2. Подключение picocli

- [ ] Показать `pom.xml`, объяснить его назначение по материалу «Maven и pom.xml» — включая, зачем вообще нужны
  системы сборки.
- [ ] Показать зависимость picocli, обзорно — основные аннотации и классы (`@Command`, `@Option`, `@Parameters`,
  `Callable`, `CommandLine`).

### Этап 3. Обсуждение: какие паттерны GoF применимы к CLI

- [ ] Провести открытое обсуждение по вопросам из плана, зафиксировать на доске таблицу «задача → паттерн-кандидат».
- [ ] Отметить, что Iterator и Command в проекте уже реализованы — на занятии их обсуждают и разбирают, а не пишут
  заново.
- [ ] Кратко показать материал «Паттерны проектирования GoF» — не пересказывать целиком.

### Этап 4. Совместная реализация: Factory Method

- [ ] Реализовать вместе со студентами тела `create()` в `StockFactory`, `BondFactory`, `EtfFactory` — конструирование
  `Stock`/`Bond`/`Etf` по строковым аргументам команды.
- [ ] Обсудить самрегистрацию фабрик через `static`-блок (`InstrumentFactories`) как пример автоматизации добавления
  нового типа.

### Этап 5. Итератор по репозиторию — показ и разбор готовой реализации

- [ ] Показать `InstrumentRepository` (`Iterable`/`Iterator`), разобрать на паре эквивалентных фрагментов, что
  `for-each` — синтаксический сахар над `Iterator`.

### Этап 6. Самостоятельная работа: Strategy — фильтрация по типу

- [ ] Раздать студентам функциональные требования и интерфейс `InstrumentFilter` → студенты самостоятельно
  реализуют `TypeFilter` и `NoOpFilter` (сравнение по `getType()`, не по `getClass()`).
- [ ] Сверить результат с эталонной реализацией.

### Этап 7. CLI-команды — показ и разбор готовой реализации (Command)

- [ ] Показать `SearchCommand`, `AddCommand`, `ListCommand`, `MarketPulseCli`, `demo/Main` — разобрать, как команды
  регистрируются вручную через `addSubcommand` и почему не через атрибут `subcommands`.

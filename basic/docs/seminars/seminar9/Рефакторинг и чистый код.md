# Рефакторинг и чистый код

---

## Что такое рефакторинг

Рефакторинг — изменение внутренней структуры кода без изменения его внешнего поведения. Цель не в том, чтобы добавить
функциональность, а в том, чтобы снизить стоимость будущих изменений: сделать код читаемее, убрать дублирование,
прояснить границы. Наблюдаемый результат до и после — один и тот же; меняется только форма.

---

## Зачем

Код читают и меняют куда чаще, чем пишут. «Работает» — необходимое, но не достаточное условие: непонятный код работает
ровно до следующего изменения, которое в нём страшно делать. Рефакторинг оптимизирует стоимость сопровождения — то, во
что реально упирается развитие проекта.

---

## Технический долг

**Технический долг** — накопленные компромиссы «сделали быстро, но не чисто». Как финансовый долг, он берётся осознанно
ради скорости и обслуживается процентами — замедлением и ошибками при каждом изменении. Немного долга — нормально;
неконтролируемый долг превращает любую правку в риск.

Осознанный долг фиксируют списком с планом погашения. Неосознанный — «код какой-то не такой» без конкретики — опаснее:
его нельзя ни оценить, ни спланировать.

---

## Типовые приёмы

- **Extract Method** — вынести повторяющийся или самостоятельный кусок в отдельный метод с осмысленным именем.
- **Rename** — дать переменной/методу имя, отражающее смысл.
- **Remove Duplication** — свести повторяющуюся логику в одно место (частный случай Extract Method).
- **Inline** — убрать лишний уровень косвенности, если он не несёт смысла.

Самый частый повод — дублирование: одинаковый код в нескольких местах меняется несогласованно и порождает ошибки.

---

## Безопасный рефакторинг

Менять структуру безопасно можно только тогда, когда поведение чем-то зафиксировано. Три правила:

- **Не менять поведение и структуру одновременно.** Сначала переписать реализацию при неизменном контракте, убедиться,
  что результат тот же, и лишь отдельным шагом менять контракт.
- **Малые шаги.** Крупное переписывание — серия мелких эквивалентных преобразований, после каждого код рабочий.
- **Опора на тесты.** Автоматические тесты прогоняются до и после и мгновенно показывают, если поведение изменилось.

```java
// Дублирование в трёх командах — повод для Extract Method
... .stream().map(quoteService::quoteFor).flatMap(Optional::stream) ...

// После: логика в одном месте
public List<Quote> quotesFor(Collection<String> tickers) {
    return tickers.stream().map(this::quoteFor).flatMap(Optional::stream).toList();
}
```

---

## Почему тесты решают

Без тестов рефакторинг — ставка: «кажется, ничего не сломал». С тестами это рутина: сломанное поведение краснеет сразу.
Намеренная ошибка (`flatMap(Optional::stream)` → `map(Optional::get)`) роняет тест на первом же ненайденном значении — то,
что без теста всплыло бы только в проде. Именно тесты превращают страх «а вдруг сломал» в проверяемый факт.

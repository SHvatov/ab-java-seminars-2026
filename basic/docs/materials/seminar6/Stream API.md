# Stream API

Stream API — часть стандартной библиотеки (`java.util.stream`), позволяющая обрабатывать последовательности данных
декларативно: описывать *что* нужно получить из коллекции (отфильтровать, преобразовать, сгруппировать, свернуть в
результат), а не *как* пошагово это накапливать. Этот материал разбирает устройство стрима, виды операций, коллекторы и
типичные ошибки.

## 1. Что такое стрим и чем он не является

Стрим — конвейер обработки элементов, а не хранилище. Он не содержит данных: элементы поступают из источника (коллекции,
массива, генератора) и «протекают» через цепочку операций. Стрим не изменяет источник — результат обработки возвращается
отдельно, а исходная коллекция остаётся прежней.

Ключевое отличие от цикла — уровень описания. Императивный цикл описывает механику накопления (завести аккумулятор,
пройти по элементам, на каждом шаге обновить состояние). Стрим описывает намерение через именованные операции (`filter`,
`map`, `groupingBy`), а механику берёт на себя библиотека. Для типовой обработки данных это делает код короче и ближе к
формулировке задачи.

## 2. Устройство конвейера: источник, промежуточные, терминальная

Конвейер состоит из трёх частей:

1. **Источник** — `collection.stream()`, `Arrays.stream(array)`, `Stream.of(...)`, `Stream.iterate(...)`.
2. **Промежуточные операции** — возвращают новый стрим, соединяются в цепочку, ленивы.
3. **Терминальная операция** — ровно одна, запускает конвейер и возвращает результат или производит побочный эффект.

```java
void example(List<Instrument> instruments) {
    List<String> rubTickers = instruments.stream()          // источник
            .filter(i -> i.getCurrency() == Currency.RUB)   // промежуточная
            .map(Instrument::getTicker)                     // промежуточная
            .sorted()                                       // промежуточная
            .toList();                                      // терминальная
}
```

Без терминальной операции конвейер не выполняется: цепочка промежуточных операций — лишь описание того, что нужно
сделать.

## 3. Ленивость и одноразовость

Промежуточные операции **ленивы**: они не обрабатывают элементы в момент вызова, а лишь достраивают конвейер.
Фактическая обработка начинается при вызове терминальной операции и идёт по элементам — каждый элемент проходит через всю
цепочку, прежде чем берётся следующий. Это даёт два эффекта:

- **Отсутствие промежуточных коллекций.** `filter().map().toList()` не создаёт отдельный список после `filter` и ещё
  один после `map` — элементы протекают насквозь.
- **Короткое замыкание (short-circuit).** Операции вроде `limit(n)`, `findFirst`, `anyMatch` останавливают обработку,
  как только результат определён, не проходя весь источник.

```java
void example(List<Quote> quotes) {
    Optional<Quote> firstGainer = quotes.stream()
            .filter(q -> q.getChangePercent().signum() > 0)
            .findFirst();   // остановится на первом подходящем, не пройдя остальные
}
```

Стрим **одноразовый**: после терминальной операции он считается использованным, и повторный вызов терминальной операции
бросает `IllegalStateException`. Для повторной обработки создаётся новый стрим из источника.

## 4. Промежуточные операции

- `filter(Predicate)` — оставляет элементы, для которых предикат истинен.
- `map(Function)` — преобразует каждый элемент; `mapToInt`/`mapToDouble` дают числовой стрим.
- `flatMap(Function)` — преобразует элемент в стрим и «расплющивает» результат в один стрим (см. раздел 8).
- `sorted()` / `sorted(Comparator)` — упорядочивает; требует пройти все элементы (не ленива по эффекту), поэтому на
  бесконечном стриме без ограничения не завершится.
- `limit(n)` / `skip(n)` — берёт первые `n` / пропускает первые `n`.
- `distinct()` — убирает дубликаты по `equals`/`hashCode`.
- `peek(Consumer)` — заглядывает в элементы без изменения (для отладки; не для логики).

```java
void example(List<Quote> quotes) {
    List<Quote> topThreeGainers = quotes.stream()
            .filter(q -> q.getChangePercent().signum() > 0)
            .sorted(Comparator.comparing(Quote::getChangePercent).reversed())
            .limit(3)
            .toList();
}
```

## 5. Терминальные операции

- `forEach(Consumer)` — действие над каждым элементом (побочный эффект).
- `toList()` / `toArray()` — сбор в коллекцию/массив.
- `count()` — число элементов.
- `min(Comparator)` / `max(Comparator)` — крайний элемент, возвращают `Optional`.
- `anyMatch` / `allMatch` / `noneMatch` — проверки, возвращают `boolean`, короткозамкнуты.
- `findFirst` / `findAny` — первый/любой элемент, `Optional`.
- `reduce(...)` — свёртка всех элементов в одно значение.

`reduce` полезен там, где стандартного коллектора нет, — например, для суммы `BigDecimal`:

```java
void example(List<Quote> quotes) {
    BigDecimal totalPrice = quotes.stream()
            .map(Quote::getPrice)
            .reduce(BigDecimal.ZERO, BigDecimal::add);
}
```

## 6. Коллекторы

`collect(Collector)` собирает результат конвейера по правилу коллектора. Основные из `java.util.stream.Collectors`:

- `toList()`, `toSet()`, `toMap(keyFn, valueFn)`, `toCollection(supplier)`.
- `groupingBy(classifier)` — группирует в `Map<K, List<V>>`; со вторым коллектором меняет тип значения группы:
  `groupingBy(key, counting())` → `Map<K, Long>`, `groupingBy(key, averagingDouble(fn))` → `Map<K, Double>`.
- `partitioningBy(predicate)` — частный случай группировки на две группы по логическому условию.
- `counting()`, `summingInt/Double`, `averagingInt/Double`, `reducing(...)` — коллекторы-агрегаты, обычно вложенные в
  `groupingBy`.
- `joining(sep, prefix, suffix)` — склеивает строковые элементы.

```java
void example(List<Quote> quotes) {
    // Сколько инструментов каждого типа.
    Map<String, Long> byType = quotes.stream()
            .collect(Collectors.groupingBy(
                    q -> q.getInstrument().getClass().getSimpleName(),
                    Collectors.counting()));

    // Тикеры одной строкой.
    String line = quotes.stream()
            .map(q -> q.getInstrument().getTicker())
            .collect(Collectors.joining(", ", "[", "]"));
}
```

## 7. Числовые стримы и точность

`mapToInt`/`mapToLong`/`mapToDouble` дают специализированные стримы (`IntStream`, `DoubleStream`) с методами `sum()`,
`average()`, `summaryStatistics()`. Они избегают боксинга и удобны для числовых агрегатов:

```java
void example(List<Quote> quotes) {
    double avgChange = quotes.stream()
            .mapToDouble(q -> q.getChangePercent().doubleValue())
            .average()
            .orElse(0.0);
}
```

Важная оговорка о точности: перевод `BigDecimal` в `double` (`doubleValue()`) теряет точность. Для отображаемого
среднего процента это допустимо, но для денежных величин (суммарная стоимость, а не усреднённый процент) действует
правило доменной модели — оставаться на `BigDecimal` и агрегировать через `reduce(BigDecimal.ZERO, BigDecimal::add)`,
а не переводить в `double`.

## 8. flatMap и Optional.stream()

`flatMap` применяется, когда каждый элемент преобразуется не в одно значение, а в стрим значений, и все эти стримы нужно
слить в один. Частая идиома — отбросить отсутствующие значения без явных проверок на `null`, опираясь на то, что
`Optional.stream()` возвращает пустой стрим для `Optional.empty()` и одноэлементный — для присутствующего значения:

```java
void example(List<String> tickers, QuoteService quoteService) {
    List<Quote> found = tickers.stream()
            .map(quoteService::quoteFor)   // String -> Optional<Quote>
            .flatMap(Optional::stream)     // Optional.empty() исчезает, значение остаётся
            .toList();
}
```

Без `flatMap` пришлось бы фильтровать по `isPresent()` и затем разворачивать через `get()` — два шага вместо одного и
потенциальный источник ошибок.

## 9. Типичные ошибки

- **Переиспользование стрима.** Стрим одноразовый; сохранять его в переменную и вызывать терминальную операцию дважды
  нельзя — будет `IllegalStateException`. Повторная обработка — из нового `stream()`.
- **Побочные эффекты в промежуточных операциях.** `map`/`filter` должны быть чистыми (без изменения внешнего
  состояния). Изменение внешней коллекции из лямбды внутри стрима ломает предсказуемость и несовместимо с параллельным
  выполнением.
- **Ожидание, что стрим изменит источник.** `list.stream().sorted()` не сортирует `list`. Чтобы получить результат, его
  надо собрать терминальной операцией.
- **`peek` для логики.** `peek` предназначен для отладочного подглядывания; строить на нём поведение не следует — при
  коротком замыкании он может не выполниться для всех элементов.
- **Перевод денег в `double` ради `sum()`.** Для денежных сумм — `reduce` над `BigDecimal`, а не `mapToDouble().sum()`.

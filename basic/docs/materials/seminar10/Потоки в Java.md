# Потоки в Java

Поток — независимая последовательность исполнения внутри программы. Многопоточность позволяет делать несколько вещей
одновременно: пока один поток ждёт ответа по сети, другие работают. Материал разбирает виды потоков, их жизненный цикл,
создание и управление, безопасное распараллеливание и корректное прерывание.

## 1. Зачем нужны потоки

Однопоточная программа делает одно дело за раз. Если задача упирается в ожидание (сеть, диск), процессор простаивает.
Многопоточность позволяет: (а) параллельно выполнять независимые задачи на разных ядрах; (б) не блокировать программу на
время ожидания. Наш `quotesFor` загружает котировки по одному тикеру за раз, и почти всё время потоки ждут сеть —
классический случай, где параллелизм даёт кратное ускорение без единого лишнего вычисления.

---

## 2. Поток Java и поток ОС

Классический поток Java — тонкая обёртка над потоком операционной системы (1:1). За распределение потоков по ядрам CPU
отвечает планировщик ОС; какой поток исполняется в данный момент, программа не контролирует. Поток ОС — тяжёлый ресурс:
собственный стек (обычно около мегабайта), структуры в ядре, накладные на переключение контекста. Поэтому потоков не
может быть очень много, и их не создают по одному на каждую мелкую задачу (эту проблему решают пулы и виртуальные потоки
— в семинаре про Executor Framework).

## 3. Жизненный цикл потока

Поток проходит состояния:

- `NEW` — создан, но не запущен;
- `RUNNABLE` — готов исполняться или исполняется (планировщик решает, когда дать ядро);
- `BLOCKED` — ждёт освобождения монитора (следующий семинар);
- `WAITING` / `TIMED_WAITING` — ждёт события или таймаута;
- `TERMINATED` — завершился (нормально или из-за исключения).

`BLOCKED` и `WAITING` — простой: поток ничего не делает, но занимает ресурсы.

## 4. Создание и запуск

Современный способ — билдер `Thread.ofPlatform()` (Java 21+):

```java
void example(Runnable task) {
    Thread thread = Thread.ofPlatform().name("worker").start(task);   // создать и запустить
    Thread later = Thread.ofPlatform().unstarted(task);               // создать, запустить позже
    later.start();
}
```

- `start()` создаёт и сразу запускает; тело потока — переданный `Runnable`.
- `unstarted()` создаёт без запуска.
- До запуска можно задать `name`, `daemon(true)`, `priority(...)`.

**Виды потоков:** платформенные (обёртка над ОС), daemon-потоки (JVM не ждёт их завершения — годятся для фоновых задач,
но не для того, что обязано доработать), виртуальные (лёгкие, Java 21 — отдельная тема).

**`Runnable` vs `Callable`:** `Runnable.run()` не возвращает значение и не может бросать checked-исключения (неудобно
при работе с `InterruptedException`); `Callable` это умеет — с ним познакомимся в семинаре про Executor Framework.

## 5. Ожидание завершения: join

`join()` блокирует текущий поток, пока целевой не завершится. Так собирают результаты после параллельной работы:

```java
void example(Thread[] threads) throws InterruptedException {
    for (Thread thread : threads) {
        thread.join();   // ждём завершения каждого
    }
    // после цикла все потоки гарантированно закончили
}
```

`join` устанавливает happens-before: всё, что поток сделал до завершения, видно после `join` (важно для корректной сборки
результатов).

## 6. Параллелизм без общего состояния

Самый безопасный параллелизм — когда потоки не делят изменяемое состояние. Если каждый поток пишет только в свою ячейку
массива результатов, два потока никогда не обращаются к одной и той же памяти на запись, поэтому гонок нет и
синхронизация не нужна:

```java
void example(List<String> tickers, QuoteSource source) throws InterruptedException {
    Quote[] results = new Quote[tickers.size()];
    Thread[] threads = new Thread[tickers.size()];
    for (int i = 0; i < tickers.size(); i++) {
        int index = i;
        threads[i] = Thread.ofPlatform().start(() ->
                source.fetch(tickers.get(index)).ifPresent(q -> results[index] = q));
    }
    for (Thread thread : threads) {
        thread.join();
    }
    // results заполнен; порядок сохранён индексацией
}
```

Как только появляется общее изменяемое состояние (один счётчик, одна коллекция на всех потоках), возникают гонки — что
именно ломается и как чинить, разбирается в следующем семинаре.

## 7. Прерывание потока

Поток нельзя остановить насильно (методы `stop`/`suspend` давно объявлены небезопасными и удалены). Единственный
корректный способ — **кооперативное прерывание**:

```java
void example(Thread worker) {
    worker.interrupt();   // выставляем потоку флаг «пора остановиться»
}
```

- `interrupt()` выставляет флаг прерывания.
- Блокирующие методы (`sleep`, `join`, `wait`, сетевые ожидания) реагируют, бросая `InterruptedException`.
- При броске `InterruptedException` флаг **сбрасывается**, поэтому его восстанавливают:

```java
void example() {
    try {
        Thread.sleep(1000);
    } catch (InterruptedException e) {
        Thread.currentThread().interrupt();   // восстанавливаем флаг
        return;                               // и корректно выходим
    }
}
```

Проглоченный `InterruptedException` (пустой `catch`) — частая ошибка: такой поток невозможно корректно остановить, а
вызывающий код теряет сигнал прерывания. Цикл, который долго работает без блокирующих вызовов, проверяет флаг сам:
`if (Thread.currentThread().isInterrupted()) return;`.

## 8. Атомарный счётчик

Когда несколько потоков увеличивают один счётчик (например, «сколько задач завершено» для прогресс-бара), обычный `int++`
теряет обновления: операция составная (прочитать, прибавить, записать), и два потока могут прочитать одно значение и
записать одинаковый результат. `AtomicInteger` выполняет инкремент атомарно:

```java
void example() {
    AtomicInteger completed = new AtomicInteger();
    // из любого потока по завершении задачи:
    int done = completed.incrementAndGet();   // атомарно +1 и вернуть новое значение
}
```

Почему обычный `int` ломается на уровне модели памяти и как атомарность устроена внутри (CAS) — здесь не
разбирается; достаточно правила: **счётчик, изменяемый из нескольких потоков, — `AtomicInteger`, а не `int`.**

## 9. Частые проблемы

- **Race condition** — результат зависит от того, какой поток успел первым (общее изменяемое состояние без
  синхронизации). Следующий семинар.
- **Проглоченное прерывание** — пустой `catch (InterruptedException)`; поток нельзя корректно остановить.
- **Поток на каждую задачу** — при большом числе мелких задач создание потоков дороже самой работы; нужен пул.
- **Забыли `join`** — главный поток продолжает до того, как воркеры закончили, и читает неполный результат.

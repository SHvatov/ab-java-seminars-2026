# Написание лекционных материалов (презентационные файлы)

**Что производим:** `{basic|advanced}/docs/seminars/seminarN/<Тема>.md` — по файлу на тему (`ООП.md`,
`Принципы SOLID.md`, `Optional.md`, `Generics.md`, …). Семинарист проецирует их на экран во время занятия. В будущем
планируется дополнить картинками/схемами.

## Назначение и стиль

- **Lean и scannable** — рассчитаны на «взгляд мельком» с проектора, не на вдумчивое чтение.
- **Student-facing** — никаких ремарок для преподавателя (те живут только в `План семинара.md`).
- **Самодостаточны** — не ссылаются на номера семинаров или структуру курса (в отличие от плана).
- Обычно это теория, **вынесенная из инлайна плана семинара**: после выноса план ссылается на файл вместо повтора
  текста («Презентация по материалу [«...»](./...md)»). Для семинаров 5+ (где нет черновиков в `raw/`) теория так же
  формулируется на этапе плана и выносится сюда — источника-заготовки нет, пишется с нуля.
- В конце — указатель на подробный deep-dive в `docs/materials/` («Подробнее — в материале [«...»](../../materials/...)»).

## Формат

1. `# <Тема>`
2. `---`
3. Разделы `## <Подтема>` с короткими абзацами (2–4 предложения), код-вставками и таблицами.
4. Код обёрнут корректно (полный класс/интерфейс либо `void example() {}`).
5. Финальный указатель на материал `docs/materials/`.

## Каталожные темы (важное различие)

Для обзорных тем вроде «Паттерны GoF» — **не** вываливать полный код каждого элемента (он уже есть в плане и в deep-dive):
назвать каждый паттерн/элемент, дать одну строку про решаемую задачу в терминах проекта, а в конце — короткий
appendix-список полного канонического набора (например, все 23 паттерна GoF по группам) без раскрытия. Подтверждено
пользователем: «достаточно рассказать про основные типы шаблонов и какую задачу решает каждый; в конце — короткий
список всех шаблонов».

## Проверки

- Код компилируется против реальной доменной модели (см. `[[domain-model-drift]]` в CLAUDE.md).
- Нет ремарок для преподавателя и ссылок на номера семинаров.
- Продвинутый трек пишется независимо от базового (перенос по смыслу), может содержать доп. темы (байт-код, Vavr и т.п.).
- Тон академический, безличный, без эмодзи; термины на английском, текст на русском.
